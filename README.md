# Earnings Atelier

複数企業の株価と公表済み業績を自動更新するダッシュボードです。左側の会社メニューから対象企業を切り替え、最新株価・前日比、業績推移、四半期内訳、公式IR PDF、直近1年の日足・MA・フィボナッチを確認できます。

## 主な機能

- Supabaseの公開テーブルから会社、四半期業績、公式IR PDFを読み込みます。
- 年度は会計年度の開始年です。2022年度は、3月決算企業では2023年3月期に相当します。公式IRアーカイブで原本を取得・解析できた2022年度以降の実績を年度選択に追加します。累計から単独四半期への変換は、同じ年度の直前累計を確認できる場合だけ行います。未取得の期は推測で埋めません。
- 四半期の収入・支出はサンキーグラフで表示します。売上収益と増益調整が、営業費用・税金等・純利益へ配分される流れを、金額に比例した帯の太さで確認できます。会社・年度・四半期を切り替えるとグラフも更新されます。
- サンキー中央の合流部は、配分総額に応じて緩やかに太くし、高さ144〜240px・横幅20〜28pxに収めます。科目が多い場合は描画領域を広げて合流部の太さを保ちます。損益・キャッシュフローとも、図の中では全科目に同じ縮尺を使い、帯の金額比率と流入・流出の総量を維持します。図ごとに縮尺が変わるため、企業や期間の金額比較には表示金額を使ってください。
- スマホではサンキー全体を画面幅に合わせて表示します。「拡大表示」を押すと科目を読みやすい幅に広げ、図の中を左右にスワイプできます。「全体表示」で元へ戻ります。長い科目は図では省略する場合があり、下の内訳表で全文・金額・原本ページを確認できます。画面回転や言語切り替え後も表示幅を再計算します。
- グラフをクリック・タップすると、選択した箇所の数値と期間を表示します。サンキーは帯・科目を選ぶと金額と配分割合、売上・利益は棒や点の数値、利益率は対象四半期の割合、日足株価は対象日の始値・高値・安値・終値・MAを表示します。金融値は百万円／JPY millionの省略しない数値で表示します。スマホは画面下に詳細を表示し、「×」・グラフ外のタップ・Escapeで閉じます。キーボードではTabでグラフへ移動し、左右矢印で項目を選べます。企業・期間・言語の変更やグラフ再描画時には古い値の表示を閉じます。
- 公式決算書を取得できる企業では、売上原価・販管費・金融収益／費用・税金・非支配持分などの細目を表示します。原本の科目表とページリンクも確認できます。減益項目は右側、増益項目は左側に表示します。赤字は「純損失（不足額）」として収入とは区別します。内訳が取得できない場合は集計値を使用し、差額は計算値であることを明示します。狭い画面では横スクロールできます。
- スマホでPDF解析に失敗しても、公式原本から事前に抽出した内訳を表示します。`/api/official-reports` の `reports` は、対象会社と、現在の公式一覧または確認済みアーカイブの原本URLが一致する科目・金額・ページのみ返します。事前解析されていない新しい資料はブラウザ側でも解析を試みます。保存済み内訳には原本の対象期間を表示し、新しい期間の実績として流用しません。
- DBを取得できない場合は、`app.js` 内の予備データを表示します。
- 日足ローソク足に、終値の5・25・100取引日単純移動平均（SMA）を重ねます。MA5は青、MA25はオレンジ、MA100は紫です。MA100の準備期間を含む2年分の日足を取得し、直近1年だけ表示します。期間不足・欠損の区間はMAをゼロとして描きません。株価と日足は1時間ごとに確認し、失敗時は前回値を保持します。
- フィボナッチは表示する1年の日足の最高値（high）を0%、最低値（low）を100%として、0・23.6・38.2・50・61.8・78.6・100%を表示します。最高・最低の日付を画面に表示し、同値なら線を表示しません。水準は灰色の破線です。日足をクリックするとOHLCとMA3本、水準をクリックするとその価格と極値を確認できます。
- Cloudflare Workerが各社の公式IRページを毎日確認し、発見した決算PDFのリンクを資料一覧へ追加します。
- 決算資料は取得元を結合した後、公表日の新しい順に並べます。公表日がない資料は資料名・原本URLの日付、決算年度・四半期を使って配置し、時期が分からない資料は末尾に置きます。取得日時・更新日時で古い資料が先頭へ移動することはありません。
- 最新株価はYahoo Financeから取得し、表示中は1時間ごとに確認します。株価の配信時刻と取得時刻は日本時間で表示します。無料配信には遅延があるため、約定ごとのリアルタイム配信ではありません。
- 決算情報は1日ごとに再確認します。登録済みの公式IR業績を優先し、それより新しい単独四半期の円建て業績をYahoo Financeで補います。外部業績の出典は画面に表示します。
- 配信元の最新通期実績（売上・営業利益または税引前利益・純利益）は別のパネルで表示します。四半期データがない企業でも通期業績を取得できます。通期と四半期を混ぜて比較しません。
- 「自動更新」で停止・再開できます。非表示タブでは定期取得を止め、復帰・再開時は株価1時間／決算1日の期限を過ぎた情報だけ確認します。初回表示・企業切り替え・手動更新は随時取得し、配信側の保存値も利用します。取得失敗時は前回値を保持し、更新失敗と表示します。

## ローカル表示

### 過去の公式決算データ

2026年10月15日の取得では、トヨタ、MUFG、ソフトバンクグループ、ファーストリテイリング、アドバンテスト、SMFG、みずほ、キーエンス、伊藤忠、信越化学、三菱商事、日立、NTTの13社で2022〜2024年度の第1〜第4四半期を収録しています。2025年度以降も取得できた期を収録していますが、SMFGの2025年度第1・第2四半期は不足しています。村田は2023年度以降を収録しています。キオクシア、東京エレクトロン、ソニー、リクルート、東京海上、三井物産と村田の2022年度は、取得制限・原本形式・資料一覧の取得不足により未収録です。

`npm.cmd run sync:history` は、公式サイトのリンクと年度選択のURLをたどり、2022年度以降の決算書を `statement-data.json` に保存します。対象を限定する場合は `npm.cmd run sync:history -- toyota`、既存の原本を再解析する場合は `npm.cmd run sync:history -- --reparse hitachi` を実行します。PDF.jsを準備してから同期してください。同期後の公開反映には別途デプロイが必要です。

`reportsByCompany` に原本URL・ページ・科目・当期の金額、`documentsByCompany` に発見元の公式ページ、`coverageByCompany` に年度別の取得済み単独四半期を保存します。解析できなかった資料は `failures` に残し、成功済みの値を保持します。配信時は会社・発見元・原本URLが一致する履歴だけを返し、端末では事前解析済みの全期間を先に表示します。スマホで再解析する未取得PDFは最新4件までです。

公式PDFの日本語解析ライブラリは次のコマンドで準備します（Node.js 22以降）。WindowsでPowerShellのスクリプト制限がある場合は `npm.cmd`、`npx.cmd` を使ってください。

```powershell
npm.cmd ci --ignore-scripts
npm.cmd run build
npx.cmd wrangler dev
```

`vendor/` にPDF.jsの修正済み解析エンジン・Worker・日本語文字マップ・標準フォントを配置します。Cloudflare Workerは公式ページの確認・原本の中継・事前解析済み内訳の配信を行います。ブラウザ側のPDF解析は未解析資料の補完に使用します。株価・登録済み業績は先に表示され、決算書の内訳も反映されます。`AbortSignal.timeout` がないWebViewでは `AbortController` によるタイムアウトを利用します。

`vendor/` はビルドで生成するためGit管理から除外しています。新しいチェックアウトでも上の依存関係インストールとビルドを実行してから起動・公開してください。`tmp/` と検証用のスクリーンショットもGit管理には含めません。テストの再現に必要な `test-fixtures/` は管理対象です。

公式決算書の事前解析データを更新する場合は、`npm.cmd run build`、`npm.cmd run sync:statements`、`npx.cmd wrangler deploy` の順に実行します。`sync-statements.mjs` が20社の確認済み公式PDFを取得し、比較列・証券コード・表紙の主要値を照合した `statement-data.json` を作成します。解析できなかった原本は `failures` に記録し、成功済みの出典付き内訳は保持します。この事前解析は同期コマンド実行時に更新され、Cronによる公式リンク一覧の1日更新とは別です。

Pythonが入っていれば次のコマンドで画面を確認できます。

```powershell
python -m http.server 5173
```

ブラウザで `http://localhost:5173` を開いてください。

この方法ではCloudflare Workerが起動しないため、株価と外部業績APIは利用できません。DB表示・株価・外部業績をまとめて確認する場合は、Wranglerが利用できる環境で `npx wrangler dev` を実行します。

## 設定

設定は `config.json` に集約しています。`config.js` は使いません。

```json
{
  "supabase": {
    "url": "https://PROJECT.supabase.co",
    "key": "SUPABASE_ANON_KEY"
  }
}
```

`config.json` はブラウザにも配信される公開設定です。RLSを設定した公開読取用のSupabase anon keyだけを使用し、service role keyやSecretは入れないでください。

## データの扱い

- 業績推移と四半期内訳は、`earn_quarterly_results` を使います。
- 公式IR PDFリンクは、`earn_ir_documents` と四半期業績の `source_url` を使います。
- 事前解析済みの公式決算短信・要旨は全期間を表示します。端末で補完解析する未取得PDFは最新4件までとし、PDFの損益計算書から当期実績を抽出します。会社の証券コード、実績期間、百万円単位、比較列、表紙の主要金額を照合します。株価・補完業績はYahoo Financeを利用します。取得できない企業・期間は登録済み業績を表示し、未取得を明示します。
- Yahoo Financeの補完には実績の3か月単独値だけを採用し、円から百万円へ変換します。予想値・外貨建て・主要値の欠損は採用しません。登録済み業績はYahoo Financeで上書きしません。公式決算書が照合できた場合は、同じ期間の主要値と細目を一緒に公式原本で置き換え、出典を表示します。DBへの書き込みやスキーマ変更はありません。
- 年度は会計年度の開始年で統一し、「2026年度（2027年3月期）」のように年度末も併記します。3月期企業の2026年度は2026年4月〜2027年3月です。2026年10月時点で未公表の四半期・通期実績は作りません。キーエンスの20日締めなどは原本の実績期間を使用します。ファーストリテイリングの2026年8月期は開始年基準では2025年度です。
- 第1四半期は単独四半期として反映します。第2〜第4四半期は同じ会計年度・同じ開始日の直前累計を取得できた場合だけ差分へ変換し、両原本を保持します。直前累計が欠損している場合は単独四半期を推測しません。「決算書の収入・支出内訳」で累計の原本を確認でき、「この決算書の期間をサンキーに表示」で期間を明示して累計図に切り替えられます。
- 損益の集計行と内訳を二重計上せず、同じ「その他」も科目の区分を保持します。解析した細目だけでは純利益に一致しない場合は「未分類差額（計算）」、3百万円以内の差は「丸め差額（計算）」を表示します。支出の内訳は損益計算書の費用であり、現金の入出金ではありません。
- 画像だけのPDF、文字抽出ができない資料、未対応の科目・単位・比較表、JavaScriptで原本リンクを提供する一部サイトでは取得できません。取得中・取得失敗・対象期間を表示します。日本語版を優先し、予想資料・経営計画・説明会の質疑は実績として取り込みません。
- DBの初回取得に失敗した場合は、`app.js` 内の予備データを使用します。
- 初回は予備データを描画し、出典を明示します。DB再取得に失敗した場合は前回の取得値を維持します。表示する期が最新だった場合は新しい期に追従し、過去の期を選択していた場合はその選択を維持します。

## 市場データAPI

既存の `STOCK_PRICES` KVを使用するため、新しいキーやバインディングの設定は不要です。

| API | 用途 | サーバー保存値の有効時間 |
| --- | --- | --- |
| `/api/stock-quote?symbol=7203.T` | 最新株価・前日比・配信時刻 | 1時間 |
| `/api/financial-results?symbol=7203.T` | 公表済み単独四半期・通期業績と通期末 | 1日 |
| `/api/stock-prices?symbol=7203.T` | 直近1年の週足 | 6時間 |
| `/api/daily-stock-prices?symbol=7203.T` | 指標の準備期間を含む2年の日足（interval: 1d） | 1時間（手動refresh=1では60秒） |
| `/api/official-reports?company=toyota` | 公式原本リンクと事前解析した科目・金額・ページ（reports） | 公式一覧は1日、内訳は同期・配信時更新 |
| `/api/report-pdf?company=toyota&url=…` | 確認済み公式PDFの中継 | ブラウザ側1日 |

株価・日足は1時間、決算情報は1日ごとにブラウザが確認し、業績の配信元への再問い合わせは1日単位です。手動更新は日足に `refresh=1` を付け、有効時間を60秒に短縮します。週足APIは互換用途として残し、従来の平日Cronで更新します。レスポンスは `Cache-Control: no-store` でブラウザの古い保存値を避けます。株価・業績APIは `updatedAt`（取得時刻）と `stale`（更新失敗による前回値か）を返し、株価には `marketTime`（配信された株価時刻）も含みます。初回取得に失敗し保存値がなければ502を返します。

Yahoo Financeの公開エンドポイントは提供仕様の変更・アクセス制限で利用できなくなる可能性があります。配信遅延は[Yahoo Financeのデータ提供元一覧](https://help.yahoo.com/kb/finance/article-exchanges-data-delays-sln2310.html)を参照してください。無料データの更新頻度と株価そのものの配信時刻は異なります。

PDF中継は `IR_DOCUMENTS` または配信済みの確認済みアーカイブに当該会社の原本として保存され、決算書として選別されたURLだけを許可します。任意URLを中継しません。1資料12MB・100ページを上限とし、先頭70ページまで解析します。PDF.jsは6.4.299を採用し、動的評価を無効にしています。公式ページの一覧は1日、ブラウザ内の解析結果は1日キャッシュします。手動更新は解析結果を再取得しますが、公式リンク一覧とHTTP原本キャッシュの有効期間は変わりません。

`schema.sql` では次のテーブルを作成します。

- `earn_companies`: 会社マスタ
- `earn_quarterly_results`: 四半期業績
- `earn_ir_documents`: 公式IR PDFリンク

## Cloudflare Workers deploy

`wrangler.jsonc` はリポジトリ直下の静的ファイル、`worker.js` のAPI、2つのCron Triggerをまとめてデプロイします。株価は平日16:30（日本時間、UTC 07:30）に `STOCK_PRICES` KVへ保存します。公式IR資料は毎日19:00（日本時間、UTC 10:00）に各社の `ir_url` を確認し、決算PDFリンクを `IR_DOCUMENTS` KVへ保存します。画面は登録済みの資料と発見した資料を重複なしで表示します。KVが空の銘柄は、最初の株価APIアクセス時にも取得します。`npx hugo` などのビルドコマンドは不要です。

公開環境で作成したKV namespaceのIDを `wrangler.jsonc` に保存しています。同じCloudflareアカウントで再デプロイすると保存済みデータを引き継ぎます。別アカウントで利用する場合は、そのアカウントのKV namespaceに置き換えてください。既存の公開用 `config.json` のSupabase anon keyで会社マスタを読みます。

```powershell
npm.cmd ci --ignore-scripts
npm.cmd run build
npx wrangler deploy
```

ローカルでCronを試す場合:

```powershell
npx wrangler dev --test-scheduled
Invoke-WebRequest "http://localhost:8787/__scheduled?cron=30+7+*+*+1-5"
```

`npm.cmd test` でWorker・IRリンク収集・市場データ・画面更新・PDFの比較列と累計差分・サンキーの金額整合性・日英の往復切替と原本科目の保持・言語保存の失敗処理を検証します。WebViewのタイムアウト互換性・PDF解析なしの内訳表示・会社と公式URLの照合・配信内訳と6社の検証済み原本の一致も確認します。`npm.cmd run check` で公開JS・ビルド・同期スクリプトの構文を確認します。`npm.cmd run build` で公開用PDF.jsを準備し、`npm.cmd audit` で依存関係を確認できます。

`.assetsignore` は公開ファイルの許可リストです。画面のHTML/CSS/JS、公開設定、画像、`vendor/` だけを配信し、サーバーコード・テスト・検証用データ・依存パッケージは配信しません。新しいブラウザ用ファイルを追加するときは許可リストも更新してください。
- 右上の「English／日本語」で表示言語を切り替えます。企業・年度・四半期の選択や自動更新の設定を保ったまま、見出し・指標・取得状態・サンキーの主要科目を切り替えます。選択言語はブラウザのlocalStorage（`earnings-language`）へ保存し、再訪時にも反映します。保存を許可しないブラウザでも切り替え自体は利用できます。
- 英語表示の金額はJPYのM／B／T、日本語表示は百万円／億円／兆円で表示します。英語の決算書内訳には原本の日本語科目を併記します。未知の科目・公式資料の原題は原文を保持し、原本PDFへのリンクは共通です。
# 企業の追加希望

企業リストの末尾に「企業の追加希望」ボタンがあります。企業名（必須、120文字まで）と証券コード（任意、4桁の英数字）を入力すると、`POST /api/company-requests` がSupabaseの `earn_company_requests` に保存します。日本語・英語とスマホに対応し、送信失敗時は入力を残して再試行できます。希望の送信だけで企業マスタへ自動追加はしません。

既存DBには [company-requests.sql](company-requests.sql) をSQL Editorで適用してください。新規DBでも `schema.sql` に加えて適用します。保存列は `id`、`company_name`、`stock_code`、`status`（初期値 `pending`）、`created_at` です。管理者はSupabase Table Editorで受付一覧を確認し、`added` / `declined` に変更できます。公開ユーザーは企業名とコードの追加のみ可能で、希望一覧の取得・変更・削除はできません。

APIはJSON `{ "company_name": "企業名", "stock_code": "7974" }` を受け取り、成功時は201 `{ "saved": true }`、入力不正は400、DB障害は503を返します。空のコードはNULLで保存します。既存の公開Supabase設定を使用し、新しい秘密キーは不要です。

## キャッシュフローのサンキー

サンキーの「表示内容」を「キャッシュフロー」に切り替えると、公式連結CF計算書の期首現金・営業CF・投資CF・財務CF・為替や振替等の調整・期末現金を表示します。現金増加は左、減少は右に置き、左右の合計を一致させます。活動別CFは純額で、損益や減価償却を現金収入として重複計上しません。丸め差額と未分類差額があれば「計算」と明記します。

CF表示時は内訳表の決算書選択が図の対象期間になります。最初の切り替えではCFを取得できた最新資料を選び、原本の期間を図の上に明記します。累計CFを単独四半期に見せる変換は行いません。「CFあり」の資料を選べば、詳細科目・符号・原本ページを確認できます。図をクリック／タップすると金額・現金への増減が表示されます。スマホ・日本語／英語・拡大表示にも対応します。

CF未開示、列や単位が不明、期首・期末現金または3種類のCFが欠損する資料は、図を描かず未開示・未取得と表示します。`cash-flow.js` がPDFの当期列を解析し、`financial-reports.js` が `cashFlow`（百万円単位、期首・期末・3種類のCF・調整・原本行・ページ）を既存の解析結果に付加します。事前取得する `npm run sync:statements` と `statement-data.json`、公式資料APIでスマホにも解析済みデータを配信します。原本は最大70ページまで読むため、ブラウザで未取得PDFを解析する際は従来より時間がかかることがあります。
